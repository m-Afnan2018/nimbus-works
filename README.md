# Nimbus Works — Agency Operations Suite (Demo)

> **Public portfolio demo.** Every name, number and message in this app is
> generated by [`@faker-js/faker`](https://fakerjs.dev). The database resets to
> the seed data every 24 hours, and destructive actions are disabled.

Nimbus Works is a two-app suite for running a digital agency:

| App | What it does |
|---|---|
| **Workspace** | Projects, Kanban tasks with time tracking, SOP-driven workflows, departments, attendance, team chat, calendar, notes and an encrypted credentials vault. |
| **Finance** (CFO dashboard) | Clients and billing, invoices, expenses, payroll and salary slips, GST and TDS compliance, cash flow, profitability and reports. |

Both apps share one MongoDB instance. Finance uses Workspace data directly through bridge models (projects become **clients**, users become **employees**), so the two always agree. Finance mostly reads it, but creating or editing a client also creates or updates the matching Workspace project.

## Features

### Workspace
- **Projects**: status, priority, members with roles, progress roll-up, links, custom tabs and tables.
- **Tasks**: Kanban and list views, checklists, dependencies (blocked until the predecessor is done), delegation, group tasks with per-member contributions, and a start/pause/hold/finish **time tracker**.
- **SOPs**: a visual node-based builder (React Flow). Starting an SOP on a project generates the dependent task chain across departments and tracks its progress.
- **Departments**: heads, members, collaborators, reusable task templates and types.
- **Attendance**: check-in/out, lunch tracking, late detection, remote and hybrid modes, team calendar, auto-checkout and auto-absent jobs.
- **Chat**: real-time direct, group and department conversations over Socket.IO, with reactions, replies, pins, saved messages and read receipts.
- **Calendar and notes**: events with invitees, project calendars, and pinned colour notes.
- **Credentials vault**: AES-256-GCM encrypted secrets with access logs and expiry reminders.
- **Notifications**: in-app plus Web Push (PWA).
- **Roles**: admin, manager, member and viewer, with JWT access and refresh-token rotation.

### Finance
- **Overview KPIs**: revenue, net profit and margin, receivables, overdue payments.
- **Clients**: monthly billing, service breakdown, billing periods, and payment logging (online/offline).
- **Invoices**: GST (intra/interstate), TDS sections, a custom invoice designer and branding.
- **Expenses**: fixed/variable, recurring, due/paid tracking.
- **Payroll**: salary components (HRA, PF, ESI, PT, TDS), leave deductions, printable salary slips.
- **Compliance**: monthly GST filing tracker and quarterly TDS tracker with reminders.
- **Analytics**: cash flow, profitability per client, yearly client view, exportable reports.
- **Organisations**: sister entities with their own revenue and expense ledgers.
- **Service catalogue**: pricing over Workspace departments and templates, linked to SOPs.

### Demo-mode safety (`DEMO_MODE=true`)
- **Rate limits** (per visitor IP): 10 login attempts and 120 writes per minute on each API, and 20 chat messages/reactions per minute over Socket.IO.
- **Voice rooms are off** in the demo (they would connect strangers, and WebRTC needs a TURN server).
- **Blocked actions** return HTTP 403 with `{ demo: true }`, which the UI shows as a "Disabled in demo" toast:
  - every `DELETE`
  - bulk updates (mark-absent, payroll processing, recurring expenses)
  - profile, password and role changes
  - file uploads
  - push subscriptions
  - social publishing
  - SMTP settings and email reminders
- **Outbound integrations are no-ops at the service layer**: email, Web Push, and the social-media scheduler.
- **Daily reset**: the `reset` container wipes and re-seeds every database at `RESET_HOUR_UTC`.

## Architecture and memory budget

The stack is sized to run on a **512 MB VPS**:

| Container | What it runs | Idle | Peak* |
|---|---|---|---|
| `gateway` | nginx: both UIs as static files, `/api` and `/socket.io` proxy | 3 MB | 5 MB |
| `workspace-api` | Express + Socket.IO | 43 MB | 56 MB |
| `finance-api` | Express | 33 MB | 50 MB |
| `mongo` | MongoDB 7, 256 MB cache ceiling. **Only with `COMPOSE_PROFILES=local-db`**; with Atlas it doesn't run | 94 MB | 101 MB |
| `reset` | a shell `sleep`; Node only runs during the re-seed | 3 MB | 56 MB |
| **Total** | | **~175 MB** (~80 MB with Atlas) | **~270 MB** (~170 MB with Atlas) |

\*Peak while serving 2,400 API and page requests at 20 concurrent, and then running a full re-seed (measured with `docker stats`).

What keeps it small:
- **No Next.js servers at runtime.** Both frontends are built with `output: 'export'` and served by nginx. Each dynamic route (`/projects/[id]`, `/invoices/[id]/edit`, …) is prerendered once with the placeholder id `_`. nginx serves that page for every real id, and the page reads the id from the URL (`src/lib/routeParams.tsx`).
- **Capped Node heaps** (`--max-old-space-size=128`), small Mongo connection pools, a 256 MB Mongo cache, and no Mongo diagnostic-data thread.
- **Cheap healthchecks:** a TCP probe for Mongo (not `mongosh`, which starts a ~60 MB process each time) and `wget` for the APIs.
- **`mem_limit` on every service**, so a runaway process is restarted on its own instead of starving the box. Logs rotate at 5 MB.

## Database: MongoDB Atlas or local

The stack runs either against **MongoDB Atlas** (recommended on a small VPS, because it removes the biggest process) or a **local `mongo` container**.

- **Atlas:** in `.env`, set `MONGO_HOST` to the host part of your connection string, with no database name and no `?options` (for example `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net`). Then set `MONGO_OPTIONS=retryWrites=true&w=majority&maxPoolSize=5` and remove `COMPOSE_PROFILES=local-db`.
  - Pick the Atlas region closest to the server. Every API request makes several queries, so cross-region latency adds up.
  - Allow the server's IP under **Network Access**.
  - Give the database user `readWrite` on `demo_pm`, `demo_private` and `demo_cfo`.
  - URL-encode special characters in the password (`@` → `%40`).
- **Local:** keep `COMPOSE_PROFILES=local-db` and leave `MONGO_HOST` empty.

## Quick start (Docker)

On a machine with at least 2 GB of RAM (`next build` needs about 1 GB):

```bash
git clone <this-repo> nimbus-demo && cd nimbus-demo
cp .env.example .env
# replace every "change-me-64-hex-chars" with the output of: openssl rand -hex 32
# without the host nginx in front, also set TRUST_PROXY_HOPS=1
docker compose up -d --build
```

- Workspace: <http://localhost:8080>
- Finance: <http://localhost:8081>

On first boot the `reset` service sees an empty database and seeds it. Follow the progress with `docker compose logs -f reset`.

To re-seed immediately instead of waiting for the nightly reset:

```bash
docker compose exec reset node scheduler.js --now
```

## Deploying to a small VPS (512 MB) behind Nginx

A 512 MB server can **run** the stack but can't **build** it, so build the images elsewhere and copy them over.

1. **On the server**, install Docker, the Compose plugin and Nginx. Add a 1 GB swap file as a safety net for image loads and the nightly re-seed:
   ```bash
   sudo fallocate -l 1G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swappiness.conf && sudo sysctl --system
   ```
   Point two DNS records (e.g. `app.` and `finance.`) at the server.
2. **On a build machine**, build the four images and stream them to the server:
   ```bash
   docker compose build
   docker save nimbus-demo/workspace-api nimbus-demo/finance-api nimbus-demo/reset nimbus-demo/gateway \
     | gzip | ssh user@server 'gunzip | docker load'
   ```
3. **On the server**, copy `docker-compose.yml` and `.env.example` there (or clone the repo), then `cp .env.example .env` and set:
   - `WORKSPACE_PUBLIC_URL=https://app.yourdomain.com`
   - `COOKIE_SECURE=true`
   - `TRUST_PROXY_HOPS=2` (host Nginx + gateway)
   - `MONGO_HOST` / `MONGO_OPTIONS` for Atlas, and remove `COMPOSE_PROFILES=local-db` (see *Database* above)
   - fresh secrets (`openssl rand -hex 32`)
4. Start it without building: `docker compose up -d --no-build`. The stack listens on `127.0.0.1:8080` and `127.0.0.1:8081` only.
5. Copy `deploy/nginx/host-site.conf.example` into `/etc/nginx/sites-available/` and edit the `server_name`s. Enable it, then run `sudo certbot --nginx -d app.yourdomain.com -d finance.yourdomain.com`.

The in-stack `gateway` container serves each app's static UI and routes `/api` (and, for Workspace, `/uploads` and `/socket.io`) to the right API. Each app therefore runs on a single origin, which keeps cookies, CORS and websockets simple.

## Local development (without Docker)

Prerequisites: Node 20+ and a local MongoDB on `localhost:27017`.

```bash
npm run install:all
for d in workspace/backend workspace/frontend finance/server finance/client; do cp $d/.env.example $d/.env; done
# set CREDENTIALS_ENCRYPTION_KEY in workspace/backend/.env  (openssl rand -hex 32)

npm run seed                     # workspace seed, then finance seed

npm run dev:workspace-api        # http://localhost:5000
npm run dev:workspace-web        # http://localhost:3000
npm run dev:finance-api          # http://localhost:4000
npm run dev:finance-web          # http://localhost:3001
```

### Resetting without Docker

`npm run reset` re-seeds everything. To run it every 24 hours with the system cron:

```cron
0 3 * * *  cd /path/to/nimbus-demo && npm run reset >> /var/log/nimbus-reset.log 2>&1
```

## Environment variables

See [`.env.example`](.env.example) for Docker. Each service also has its own `.env.example` for local development. The important ones:

| Variable | Purpose |
|---|---|
| `DEMO_MODE` | `true` blocks destructive and outbound actions and shows the demo UI |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | Workspace auth tokens |
| `CREDENTIALS_ENCRYPTION_KEY` | 64 hex chars, encrypts the credentials vault |
| `FINANCE_JWT_SECRET`, `FINANCE_USERNAME`, `FINANCE_PASSWORD` | Finance login |
| `WORKSPACE_PUBLIC_URL` | Browser origin of the Workspace app (CORS) |
| `COOKIE_SECURE` | `true` when served over HTTPS |
| `MONGO_HOST`, `MONGO_OPTIONS` | Atlas connection (host part + options); empty means the local `mongo` container |
| `COMPOSE_PROFILES` | `local-db` runs the bundled MongoDB container |
| `TRUST_PROXY_HOPS` | Proxies in front of the APIs, for per-IP rate limits: `2` behind host Nginx, `1` for a plain local run |
| `IMAGE_TAG` | Tag for the `nimbus-demo/*` images (build on one machine, load on the VPS) |
| `RESET_HOUR_UTC`, `SEED_ON_START` | Daily reset time; initial seed (`if-empty`, `always`, `never`) |
